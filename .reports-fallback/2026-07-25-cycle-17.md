## 1. Randomised, and never run twice — `5891e4f`

`render_idle_screen()` picks a fresh caption and a fresh position on every
call. Its docstring says why, twice, quoting you both times:

> Caption rotates between the plain count and a random enticement line
> so the resting screen actively invites a new scan **rather than just
> sitting static — the actual point of this feature**.

> Caption POSITION also moves around the screen (2026-07-21, Zach's direct
> ask) … **so the idle screen doesn't look frozen in the same layout every
> single time.**

`main()` calls it once. At boot, on a scan's idle timeout, and on a stray
non-ISBN keystroke line — nowhere else. So the resting screen picks one
caption at one position and holds it, unchanged, indefinitely. Every line of
that randomisation is real, unit-tested, and has never once run twice in a row
on the actual tube.

Idle-bait is the **first** link of the funnel, and in the historical layout
`book` is the boot-default window — so this still frame is what the tube holds
until someone acts on it. It is also one unchanging frame on a phosphor tube
for hours, which is the hazard the sibling window (`crt-screensaver.py`,
breathing every 2.5s) exists to avoid.

`CRT_BOOK_IDLE_ROTATE_SECS`, default 8. Guarded on `showing_idle`, so a
question someone is reading is never painted over; `draw_idle()` restamps its
own clock, so the timeout branch and the rotation cannot double-draw in one
tick; `0` disables it, per this repo's standing rule that an automatic
behaviour keeps its manual escape hatch.

**Five pty cases, two of which fail against the parent:** with nobody touching
the console at all, it paints exactly one frame and holds it however long you
wait (`1 not greater than or equal to 4`). The other three are the guards — a
question is not painted over, `0` really disables, junk in the env does not
kill the window — plus two pure cases proving the renderer's variety is
genuine, so the second call is the only thing that was missing.

`_env_secs()` while in there: the four seconds-valued env vars were bare
`float()` at module scope, so a typo in `crt-console.sh` raised `ValueError`
before `main()` drew anything and left a bash prompt on the window that is the
console's face. Same failure `detect_screen_size()` shed last cycle.

## 2. Then I looked at what it had frozen on — `b92932b`

Two faults in one statement, `_place_text(caption[:MAX_CONTENT_WIDTH], …)`.

**It counted characters.** The budget is 30 and the tube is 40 — both in
columns — but the enticement lines are kaomoji, and `・` (U+30FB KATAKANA
MIDDLE DOT) is East Asian Wide. Measured from the real function:

```
chars=30 cols=32  '(・∀・)  got a book nearby? scan'
```

Thirty characters, thirty-two columns, padded as if it were thirty. Drawn 42
columns into a 40-column pane, and it wrapped. The same arithmetic sat under
every **book title** this console draws, and Open Library returns CJK and
fullwidth titles for perfectly ordinary scans of a feature whose entire
premise is "scan any book nearby".

**It cut where the budget ran out.** All six enticement lines are longer than
30 columns, so all six lost their ending — and four lost the ask itself:

```
'( closed book ) -> ( scanner )'     <- '-> ( trivia ). try it?' gone
'\(^o^)/  new book, new questio'     <- '-- scan one when you ...' gone
'(o.o)  ...is that a book on th'     <- 'scan it and find out' gone
'(・∀・)  got a book nearby? scan'    <- 'scan it, let's see ...' gone
```

The screen that exists to ask for a book had been saying
`( closed book ) -> ( scanner )`, with nothing to indicate it had been cut.
Same dangling-fragment fault as `fbe2cea` last cycle, one function away. The
question text beside it has word-wrapped all along — this caption was the last
guillotine on these screens.

`bg.char_width` / `display_width` / `cut_to_width` / `wrap_to_width`, with

every other screen in the project is unchanged — pinned by asserting last
cycle's own printed question screen byte-for-byte.

Carried through the rest of the same arithmetic rather than leaving it half

## 4. Stress-test of what I touched

Against this project's actual failure modes, not against it parsing:

- **Cost per rotation.** One `SELECT COUNT(*)` and one 15-line paint every 8s.
  Nothing on a Pi 3B+. `display_width` adds ~600 `unicodedata` lookups per
  frame, which is noise at this cadence.
- **Ordering against a scan.** The rotation is an `elif` on the idle-timeout
  branch and guarded on `showing_idle`, so the tick that ends a question and
  the tick that rotates the shelf can never both draw.
- **A raise inside a rotation.** It sits inside the loop body's
  `LoopGuard("book")`, so a sqlite hiccup in `book_count()` is reported on
  window 1 once per cause and the window keeps working.
- **The resize repaint still works.** Each rotation reassigns `current_frame`
  to its own draw lambda, so a client attaching mid-rotation repaints the
  shelf that is up, not a stale one.
- **A partially-typed barcode.** If a rotation fires while the terminal is
  echoing keystrokes, `draw()` clears them off the screen. The keystrokes
  themselves are in the tty buffer and the scan still lands — a real scanner's
  burst is ~100ms against an 8s cadence, so this is ~1% of scans losing their
  echo, not losing the scan. Noted rather than guarded, because the main loop
  cannot see partial input at all (stdin is line-buffered by design).
- **Infinite wrap.** `wrap_to_width` has no loop that can fail to consume a
  token; a word wider than the limit is elided onto its own line, tested with
  a 200-character word.
- **A screen too short to hold the caption.** `_pick_caption_row` sizes the
  block to the tallest unbroken run of free rows first, and a screen with no
  free row at all degrades to the historical single line rather than raising.
  Tested; never happens on the real tube.
- **Ragged centering.** A centred two-row caption centres each row
  independently, so `12 book(s) registered -- scan` / `one!` reads a little
  loose. Same thing `render_question_screen` has always done with a wrapped
  question. Left alone; question 2 below if it bothers you on the tube.
