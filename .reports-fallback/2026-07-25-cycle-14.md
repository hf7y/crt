## 2. A question for Claude, graded as a trivia answer — `2d823cc`

`crt-stt-solo.py` writes **every** recognized utterance to `stt.log` before
its wake gate runs, and two programs read that file with opposite rules. The
engine routes anything carrying the wake word to Claude. The Book Game grades
anything inside a book's answer window as a trivia answer. Nothing arbitrated
between them.

```
scan → tube: "Is Dune fiction or nonfiction?"
     → "claude, what is this book about?"
     → tube: "nope, it was fiction"
     → {"expected": "fiction", "heard": "claude what is this book about"}
     → "fiction"   ← the real answer, NOT graded
```

That last line is why this is worth more than a stray row. Cycle 13's fix
closes a round on the first graded utterance, so the Claude question *consumed
the round* and the actual answer a second later got nothing. The defect cost
the good row as well as adding a bad one.

The gate is live, not hypothetical: `crt-console.sh:193` has launched the
`stt` window with `CRT_STT_GATE=1` since 2026-07-21.

The 2026-07-21 fix already covers this exact shape for voice **commands**, by
reusing `crt-secretary.py`'s `find_playbook()` so the two halves cannot drift.
A wake-word utterance is not a command — nothing in `PLAYBOOKS` matches it,
which is precisely why it falls through to Claude. So this is that move for
the other half: `bin/crt_wake_gate.py` now holds the wake-word rule, and both
readers of `stt.log` ask it.

Sharing it matters for the aliases, not the literal word. `stt-fixups.json`
says "slide" is a calibration-confirmed mishear of "claude" — so *"slide, what
is this book about?"* wakes the console, and has to stop being graded in the
same instant, not at the next reboot. The grader re-reads the live file per
utterance, the same posture `0ccdf13` gave the gate.

Deliberately **not** an import of `crt-stt-solo.py` from the Book Game: that
module runs `arecord -l` at import time and drags in the whole capture engine.
`crt-stt-solo.py` delegates *to* the new module instead, keeping its
change-reporting `FixupsFile` where the screen is.

**14 tests** (`tests/test_book_answer_wake_word.py`), **5 fail against the
parent**. The load-bearing one is that the real answer spoken after the Claude
question still grades. The rest are the don't-break half: "landslide" is still
an answer, a non-wake fixup entry still grades, a missing fixups file degrades
to exact-word matching instead of taking the funnel's last link down.

## 3. A wrong guess is not a mishear — `85e1dfc`

`BOOK-GAME.md` is explicit about why the game logs two axes: *"a wrong
content-answer with correct STT is a fine game round and useless training
noise; a right content-answer with wrong STT is the valuable case."* The code
could not tell them apart, because `grade_answer()` computed

```
correct_stt     = normalize(expected)       == normalize(heard)
correct_content = normalize(correct_option) == normalize(heard)
```

and **both** live callers pass the same string twice —
`crt-book-answer-listen.py` and the `--answer` CLI each say
`expected=q["correct"], correct_option=q["correct"]`. The two flags were
identical in every row this console can write. The one labelled STT was a
trivia score.

What that costs is the most ordinary event a two-option game has:

```
"Is Dune fiction or nonfiction?" → "nonfiction"
  → heard perfectly, and simply wrong
  → correct_stt: false
  → counted against "STT accuracy" on the tube and in the printed report
  → listed under "STT mismatches ... the actual training data"
  → at 2 occurrences: {"nonfiction": {"intent": "fiction"}}
  → crt-stt-training-merge.py auto-merges that into the live
    bin/stt-fixups.json at confidence "auto"
```

The console teaching itself that a word it heard correctly is a mishear, from
a wrong guess — roughly half of all rounds. This is the **second live source
of junk** feeding the candidate generator found in two cycles, and a bigger
one than cycle 13's: that one needed someone to keep talking afterwards, this
one fires on ordinary correct play. It also fed `pick_response_tier()`, so
honest wrong answers held the game in short-response mode.

The always-available fallback question was worse still. *"Have you read this
before?"* has `correct=None`, so `normalize(expected)` was `""` and **every
answer anyone could possibly give it** logged `correct_stt: false`.

`grade_answer()` now takes the option list and asks the question this side can
actually answer: **did the transcription land on one of the options the person
was just offered?** Nobody but the speaker knows which one they *meant* — but
a heard string that is on the list is not evidence of a mishear, and one that
is nothing on the list is. That second set is now the only thing in
`mismatches`, which is what the fixups generator eats.

`correct_stt` is three-valued now: `None` when no options were recorded, so an
unjudgeable round reads as unknown rather than as a failure. Both accuracy
readers — `summarize_training()` and `_recent_training_stats()`, separate on
purpose to avoid an import cycle — divide by the known rounds, and a test pins
that they agree, since a hand-rolled second reader of the same file is exactly
the drift this project keeps finding.

**14 tests** (`tests/test_book_game_stt_axis.py`). Being straight about the
witness: nine of them fail against the parent only as `TypeError` on the new
argument, which proves an API change, not a defect. The two that pin the
defect go through the live listener with no new argument anywhere and fail as
plain assertions — a spoken wrong answer filed as a mishear, and two of them
reaching `generate_candidate_fixups()`.
