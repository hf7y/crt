## 1. The wake word one utterance earlier — `e220168`

`crt-stt-solo.py` writes every recognized utterance to `~/.crt/stt.log` before
it decides what to do with it, and two programs read that file with opposite
rules. Cycle 14 taught `crt-book-answer-listen.py` to leave a wake-word
utterance alone. But "addressed to the console" stopped meaning "carries the
wake word" the day `crt-wake-arm.py` landed: inside an open arm window,
follow-ups reach Claude with **no wake word at all**, deliberately — the live
2026-07-23 bug the whole mechanism exists for was four follow-ups in one
breath, every one gate-dropped for not repeating it.

So cycle 14's scenario replays with the wake word moved one utterance earlier,
and every check in `grade_pending_answer()` passes:

```
scan  -> tube shows "Fiction or nonfiction?"
      -> "claude, are you there?"      wake: not graded (14th cycle), ARMS
      -> "what is this book about?"    follow-up: routed to Claude...
      -> tube: "nope, it was fiction"          ...and graded anyway
      -> {"expected": "fiction", "heard": "what is this book about"}
      -> "fiction"  (the real answer) -- NOT graded, the round already closed
```

Reproduced against the parent, not inferred: the follow-up graded as wrong, one
row landed with `heard='what is this book about'`, and the real answer two
seconds later returned `None`.

**Both bar items are in this.** The arm window is item 1 and the Book Game
funnel is item 4, and item 1 going live is what makes item 4 start corrupting
the file this console exists to fill. `crt-book-answer-listen.py`'s own
docstring had this filed as a known gap; it is now closed rather than noted.

**How the reader finds out.** The state machine is in-process — one `ArmState`
held by the engine — so the reader is told through a published **deadline**,
not a flag. That ordering is the point: the *wake* utterance opens the window,
so the file is on disk before the follow-up it describes is ever spoken, and
there is no race against `emit()`'s own stt.log append (which happens before
the routing decision, and always did). A stale file — a crash, a reboot,
`CRT_WAKE_ARM_ENABLED` going back off — describes a moment in the past and
reads as shut, so nothing has to clean it up and the reader needs no second env
var to agree about.

`ArmState` stays pure. The engine publishes, at each of its three transition
sites and nowhere else; `crt-wake-arm.py` owns the file and both readers load
that one module.

20 cases, plus two more in the re-wake file driving the **real** `emit()`.

## 2. One typo, one dead window — `9500958`

`crt-console.sh` passes every tunable to its windows as shell text, and `bin/`
reads them as bare `int()`/`float()` at module scope. A value that isn't a
number raises `ValueError` at **import**, before the window draws anything —
and each window is wrapped in `; exec bash`, so it doesn't close. It becomes a
bash prompt where the console's face used to be, with nothing anywhere saying
why.

Two windows had already grown a private `_env_secs` for exactly this, in two
separate cycles, byte-for-byte identical down to the docstring. The funnel's
**first** link had not: `CRT_BOOK_IDLE_BAIT_SECS`, `CRT_BOOK_IDLE_BAIT_POLL`
and `CRT_BOOK_ENTICE_RATE` were bare, so a typo in any of them meant no bait,
no scan, no question and no training row, from boot.

`crt_loop_guard.py` is the sharper one. `CRT_LOOP_GUARD_TRACEBACK` went through
`int()`, so the perfectly reasonable `=true` raised **in the constructor that
book, bookanswer, bookidle and stttrain all call before their loops start** —
four windows down at once, from inside the module whose entire job is keeping a
window alive, triggered by the flag someone sets while chasing a window that
keeps dying. It now takes the words a person actually types (`true`/`yes`/`on`,
any case) and falls back to the default on anything else.

The helper lives in `bin/crt_config.py`, which opened last cycle as the landing
spot for exactly this. **Not** the sweep of all ~80 bare call sites — the
milestone parks the refactor sweep — only the ones that take a window down at
boot.

One deliberate behaviour change, flagged as question 3 below: idle-bait's POLL
gets a positive floor. Zero there is not the disable hatch it is elsewhere in
this project, it is a hot `while True` on the box that also runs the sole mic
reader.

## 3. Stress-test of what I touched

Against this project's actual failure modes, not against it parsing:

- **A live-shaped run, not just unit tests.** Started the real
  `crt-book-answer-listen.py` process against a real `books.db`, a real
  `stt.log` and a real state file. With a window open it wrote no training row
  and left the round open; with the window shut, the next utterance graded and
  logged `heard='fiction'`. That is the funnel's last link, end to end, on this
  box.
- **The sole mic reader did not get slower.** The publish is a ~10-byte local
  write on *transitions only* — at most once per utterance in `emit()`, and in
  the capture loop only when `check_arm_timeout` actually fires, not on every
  tick. Wrapped so an unwritable `~/.crt` costs the console a published window,
  never its ears.
- **A torn read is impossible, and would be harmless anyway.** `os.replace`, so
  a reader can never catch half a number. If it somehow did, it reads as shut
  — i.e. exactly the pre-existing behaviour, not something new.
- **The suite was writing into the live console's `~/.crt`.** Caught, not
  assumed: `test_wake_rearm_ceiling.py` drives the real `emit()`, so the moment
  it published, running the tests on potato would have opened a twelve-second
  arm window and suppressed trivia grading. Redirected, and the redirect is now
  pinned by two cases that assert the deadline on disk tracks what `emit()`
  did. A second copy of the same class was caught mid-cycle when a test of the
  publisher wrote a real `~/.crt/wake-arm.state` — the `path or DEFAULT` idiom
  meant an explicit `""` fell back instead of disabling. Both fixed; `~/.crt`
  verified clean after every full run since.
- **Arming off is byte-identical.** Nothing is ever published, the reader finds
  no file, and every path behaves as it did. Five cases pin that, including
  junk and unreadable state files.
- **The new import cost the bookanswer window nothing meaningful.**
  `crt-wake-arm.py` is `os`/`re`/`subprocess`/`time`; that window already loads
  `crt-secretary.py`.
- **`crt_loop_guard.py` gained a dependency** on `crt_config.py`, loaded the
  same spec way its own callers load it. If that file went missing all four
  guarded windows would die at import — but it is tracked, sits beside it, and
  `crt-book-console.py` already loads four siblings this way.
- **What I did not do:** let a follow-up answer the question on the tube, or
  pause the answer window during a conversation. Questions 1 and 2 — your call,
  not an unattended one.
