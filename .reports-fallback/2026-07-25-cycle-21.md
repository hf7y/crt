## 1. Any word you said, at the highest confidence tier — `810d935`

This game is the one place a human teaches the wake gate an alias by ear. What
you type is written to `bin/stt-fixups.json` as `"confidence": "confirmed"`, and
`crt-stt-solo.py`'s gate acts on any entry whose `intent` is the wake word with
**no further review** — `crt_wake_gate.py`'s own header uses this exact path as
its worked example. So the set of words the prompt accepts is the set of words
that can be wired into the live gate by typing them.

The displayed list was bounded to real near-misses (45–98% similar). The
acceptance was `if choice not in seen` — and `seen` is the Tailer's dict, which
by deliberate design holds **every word said in the room since the game
launched**. Run against the parent:

```
Candidates to save as confirmed mishears of 'claude':
  cloud            80%
Type a word to confirm-save it (or Enter to skip): about
Saved 'about' -> 'claude'
  -> {"about": {"intent": "claude", "confidence": "confirmed",
                "note": "... 18% similarity"}}
  -> gate("what is this book about")   True
  -> gate("tell me about the weather") True
```

It writes its own evidence against itself into the note field and saves anyway.

`save_candidates()` is now the single rule — it computes what is offered *and*
what is accepted — and `offer_to_save()` checks the answer against the list it
just printed. A refused word gets told why, and pointed at the escape hatch that
was always the right one for a genuine oddity: editing `bin/stt-fixups.json`,
which is tracked in git and reviewable, rather than a typed word at the top tier.
**Where that floor sits is question 1 below** — 0.45 was a display filter nobody
calibrated, and it is now load-bearing.

It also snapshots. The caller's dict is the live one the Tailer keeps writing
to, so iterating it directly raced a `dictionary changed size during iteration`
on the one call where the session's findings are about to be offered. Honest
scope: I reproduced that class against the parent's exact expression, but **not**
at the real poll rate — 80 rounds against a writer appending every 10ms never
hit it, because the poll sleeps 0.5s and the sort takes microseconds. It is
narrow. It is fixed as part of the same seam rather than sold as a crash you are
hitting, and the snapshot buys the thing that actually matters: the set on
screen and the set accepted are the same **in time**, not just in content.

## 2. A tone that never played — `96c75a5`

The earcon round plays a tone on each output device and asks you which one it
came out of. `crt-earcon.sh` runs under `set -euo pipefail` and ends on `aplay`,
so its exit status is a real answer to "did sound come out of there" — 1 for a
missing sox, 1 for an ALSA device that will not open, 2 for an unknown name.
`play_earcon()` sent all of it to `/dev/null` and returned nothing. Then:

```
Did you hear it, and where (tv/handset/nowhere)?
```

That is `f187a45`'s defect — a tone that never played and a tone the mic could
not hear reading identically — with **a person in the loop instead of a
threshold**. An honest "nowhere" about a tone that never sounded is a wrong
finding about the hardware, arrived at carefully, from the tool whose entire
purpose is re-verifying routing without a hands-on session. On a box with no
sox, which is this one, every round said nowhere.

It now reports the failure and `crt-earcon.sh`'s own last stderr line, and does
not put the question.

The other half: `-> logged: intended=tv, reported=nowhere` **logged nothing**.
The verdict is the whole output of the round and it lived in the tmux
scrollback. It now appends to `CRT_EARCON_ROUTING_LOG` (default
`~/.crt/earcon-routing.jsonl`), one line per device — and if that write fails
the line says **NOT logged**, because claiming "logged" while not logging is the
defect this was written to fix, one level up.

## 3. One accented name and it stops listening — `ee1037b`

The Tailer reads `~/.crt/stt.log` in a background thread. Its own docstring
explains it runs for the *whole* session rather than per-round because anything
said in the gap was otherwise "silently dropped". It read the log with strict
decoding.

That read races `crt-stt-solo.py` appending, and what it reads is **transcribed
speech** — accented names and whisper's smart quotes are ordinary content here,
not an edge case. Landing inside a multi-byte character raises
`UnicodeDecodeError`, a `ValueError`, which the `except OSError` around the read
does not catch. In a thread that kills the thread and nothing else. Measured
against the parent:

```
heard before: ['potato']
  ...writer flushes "caf\xc3" and then "\xa9 potaters"
heard after:  ['potato']          <- nothing since
tailer thread alive: False
```

Meanwhile the game prints `-- round over (still listening) --`, offers "Nothing
worth saving", runs the earcon round and says "done." — with someone still
saying the word into the mic. `ae54ef4` fixed this class for window 1 and swept
four readers; `tests/test_log_reader_decoding.py` names exactly those four, and
this one reads the same file the same way and was not among them.

It now decodes with `errors="replace"`, and resets to the start when the file has
shrunk (a replaced or truncated log left it deaf past the end for the rest of
the session — the same one line `crt-monologue.py`'s loop already has).

The thread also runs inside a `LoopGuard` now. Decoding is what killed it, but
the reason it went unnoticed is that **a dead tailer looks exactly like a quiet
room**, and that stays true of whatever kills it next. `crt_loop_guard.py` is
this project's existing answer — report the cause once, skip the iteration, keep
going — with `echo=True` here, because unlike the four background windows
somebody is looking at this pane.

  assumed: the tailer group gives 3 failures + 1 error on the parent and 4/4
  with it. §1's regression was reproduced directly against the parent before
  anything was written.

  instead of `DEVNULL`; the duck lives in `crt-earcon.sh`'s EXIT trap, which is
  what cycles 3/4 built, and a failed play still unmutes. The sox check runs
  *before* the duck, so the failure path this cycle surfaces never mutes at all.
  `subprocess.run` drains the pipe, so no deadlock on a chatty child.
- **The sole mic reader is not involved.** This game is a passive `stt.log`
  reader by design and stays one. Nothing added here opens an audio device.
- **`record_routing` cannot silently no-op.** Returns a real boolean, prints on
  failure, and a bare relative filename works (`os.makedirs("")` raises — caught
  by a test, and the guard is in).
- **The suite was writing into the live `~/.crt`.** Caught mid-cycle, and it was
  *my* new test doing it — `record_routing` with its default path put a real
  `~/.crt/earcon-routing.jsonl` on this box. Removed, and the default is now
  pinned inside tmp in the base `setUp` (along with `CRT_THOUGHT_LOG`, which
  `LoopGuard` writes to). This is the class cycle 20 caught; it recurred within
  one cycle, which is the argument for pinning defaults rather than paths.
- **What I did not do:** lower the 0.45 floor, add a below-floor confirmation
  path, or fold the routing log into a wider calibration report. Questions 1 and
  2 — your calls.
