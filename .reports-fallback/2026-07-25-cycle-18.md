## 1. Your reply, taken literally — `e724785`

Both clauses you bolded are about the screen *not being a fixed picture*.
Last cycle made it redraw. It did not make the redraw **different**.

Every draw picked caption, row and alignment independently, so a rotation
could land back on exactly the frame already on the tube. Measured, not
estimated — 200,000 draws at the real 40×15 geometry:

```
repeat rate 0.0108  ->  1 in 92 rotations  =  once every ~12 min at 8s
```

A repaint of the identical frame is indistinguishable from a hung window. On
the one screen whose job is to look alive, that is the still image the timer
exists to prevent, arriving several times an evening.

`render_idle_screen()` now takes `avoid` — the frame that is on the tube
right now — and redraws until it has a different one. Eight tries, then it
draws anyway: a geometry with only one possible frame degrades instead of
raising. `main()`'s `draw_idle()` remembers what it painted and hands it
back on the next rotation.

Three cases, one of which asserts the premise rather than the fix (without
`avoid`, 3000 draws really do collide — a guarantee nobody can fail to
notice is not worth its code), plus a pty case over the running console:
**no repaint ever lands on the frame already up**, checked pairwise across
every frame it painted.

- `CRT_SCREENSAVER_CAPTION_MOVE_SECS` (default 8, `0` pins it where it has

## 5. Stress-test of what I touched

Against this project's actual failure modes, not against it parsing:

- **Cost of the retry.** ~1% of rotations render twice. One extra 15-line
  paint every ~13 minutes; nothing on a Pi 3B+.
- **A resize mid-rotation.** The repaint calls the idle renderer at the new
  size with the old size's frame as `avoid`. Different width means never
  equal, so it returns first try — the guarantee degrades to "no guarantee"
  for exactly one frame after a resize, which is the frame that is
  guaranteed to differ anyway.
- **The scan path is untouched.** The screensaver's forwarder is a separate
  daemon thread writing `scanner.log`; nothing in it moved, and its ten
  cases still pass. A scan landing while the caption moves is unaffected.
- **A screen with no room below the art.** Falls back to whatever rows are
  free, then to the last row, then draws. Tested at 40×6 with 30 rows of
  art; never happens on the real tube.
- **`0` really pins it**, exercised by running the actual process and
  checking the caption never left `(row 14, centered)` — the historical
  layout is still what you get by asking for nothing.
- **A caption longer than the tube** is cut in columns and can no longer
  wrap, checked against a deliberately wide kaomoji string.
- **What I did not do:** consume `~/.crt/display.conf`'s overscan margin
  (backlog 5b). The caption now avoids the top row *because* of overscan,
  which is a workaround for that item, not a substitute for it.
