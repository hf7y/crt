## 1. Nothing ever checked whether the secretary was still alive — `4dfdddc`

`crt-console.sh` boots the engine with `CRT_STT_SINK=secretary`. That makes
`send_to_secretary()` in `crt-stt-solo.py` **the** destination for every
utterance that gets past the wake gate. It was:

```python
subprocess.Popen([...], stdout=DEVNULL, stderr=DEVNULL)
```

No handle kept, both streams discarded, exit status read nowhere.

`crt-secretary.py` `exec_module()`s three other `bin/` scripts at import time —
`crt-stt-confidence.py`, `crt-speculate.py`, `crt-media-player.py`. Any one of
them missing or broken kills it before `main()` runs. What the room gets in that
case: the `addressed` earcon, saying it heard you, and then nothing at all.

That is character-for-character what a gate drop looks like from where you are
standing, and a gate drop is the **opposite fact** — one is about what you said,
the other about this machine. Same distinction as the ring vs. the missed call
(`99a8dc3`) and the dead whisper server vs. the silent room (`ba33791`).

**Second defect in the same three lines:** the `Popen` call was unguarded. An
`OSError` from the spawn itself propagated straight out of the sole mic reader's
capture loop. The realistic trigger is not exotic — `ENOMEM` on a 905MB Pi
already running whisper, ten tmux windows and an active swap (FOCUS.md's own
2026-07-23 09:25 measurement: 183MB free, load 1.36). One utterance's bad luck
cost the console its hearing.

Now the process handle and a file for its stderr are kept together — the
`RingTone` shape from `99a8dc3`, for the same reason: an exit status with no
stderr beside it names no cause. `reap_dispatches()` reads the status from the
capture loop on every ~100ms chunk. **Nothing blocks:** `poll()`, never
`wait()`, because an unmatched request can legitimately hold `crt-secretary.py`
for `CRT_SECRETARY_MAX_WAIT` seconds while it waits on Claude.

A failure now names the exit code and the child's own last stderr line, on three
surfaces — the stt pane, the meter line, and window 1, where the `[you]` echo of
that same utterance is already sitting.

Tracking is capped at `CRT_DISPATCH_MAX_TRACKED` (8). Past the cap the utterance
still goes through, untracked, with a line saying so. Two rules that pulled in
opposite directions: never drop an utterance to keep a diagnostic, and never
imply an untracked one is being watched.

**15 tests with real child processes** — "the child's exit status reaches the
parent" cannot be asserted from inside one process. All 15 fail against the
parent. The fake secretary is a *Python* file, not a `/bin/sh` stub: `cdf05cc`'s
lesson from last cycle, where a shell stub exited nonzero with a SyntaxError and
every failure assertion passed without reaching the code under test.

## 2. Window 1 has been drawing 24 rows into a 15-row pane — `6aecc39`

FOCUS.md, 2026-07-23 13:40, your own words via `scheduler -i`: *"figure out
what's wrong with the text column constraints, problem on mono window and more.
suggest 40 column limit but overscan detect idea is better."* Both halves were
real and both were in `bin/crt-monologue.py` — the live script on the mono
window, and where every honest-failure line the last nine cycles added gets
written.

It sized itself **once, at import**:

- **Width**: a hardcoded 40 that never asked the terminal at all.
- **Height**: one `get_terminal_size()` call — made inside a **detached** tmux
  session. `crt-console.sh` creates this window with `tmux new-window -d` and
  runs `exec tmux attach` only at the very end, after every window exists. tmux
  sizes a detached session 80x24 regardless of what the tube is.

`crt-console.sh` already knows this. It pins `CRT_COLS`/`CRT_ROWS` for
`crt-screensaver.py` with a comment saying exactly that — *"so the screensaver
centers correctly even before the tmux client attaches (a detached session
defaults to 80x24)"* — and gives this window no such pin.

24 rows of redraw in a 15-row pane means the `\x1b[H\x1b[2J` homes to a top that
scrolls straight off. `crt-monologue.py`'s own comment describes this failure
from a previous occurrence: *"a hardcoded height taller than the actual pane
causes real terminal scroll, clipping the top of the redraw (bit us once: pane
was 11 rows, default height was 12)."* The comment survived; the fix's
assumptions did not survive the move to potato.

And the overscan safe margin in `~/.crt/display.conf` — which `crt-pager.py` and
`crt-monologue.sh` both consume — this one ignored, so on the real tube the edges
crop on top of that.

Size is now resolved **per frame**, the same fix `crt-screensaver.py` already
got (FOCUS.md item 5b). Precedence: explicit `CRT_PAGER_WIDTH`/`CRT_MONO_HEIGHT`
win, then `crt-console.sh`'s own `CRT_COLS`/`CRT_ROWS` pins, then the live
terminal, then the tube's stated geometry — with the calibrated margin applied on
top of all of them, since it describes a physical crop that is true wherever the
number came from.

**I deliberately did not add a `CRT_COLS`/`CRT_ROWS` pin to this window in
`crt-console.sh`.** Per-frame detection self-corrects within one refresh (0.5s)
of the client attaching; a pin freezes a geometry that can be wrong. Say the word
if you'd rather have the pin as well — it would make the handful of frames drawn
before attach correct too, at the cost of ignoring a differently-sized terminal
you attach from for debugging.

**13 new tests, all 13 failing at the parent.** Including the one that matters:
render at 80x24, then at 40x15, and the frame has to change shape.

## 3. New issues found

- **The two existing monologue test files test the dead one.**
  `tests/test_monologue_width.sh` and `tests/test_monologue_margin.sh` both cover
  `crt-monologue.SH` — which `test_monologue_py.py`'s own header calls a dead
  wrapper (`REFACTOR-ASSESSMENT.md` agrees). So the wrapper nobody runs had two
  dedicated width/margin test files and the script actually on window 1 had
  neither, which is how it kept a hardcoded 40 through nine cycles of people
  reading this directory. The `.sh` tests are left alone — deleting the wrapper
  is ranked-backlog item 1's job, not this cycle's.
- **`crt-monologue.py` is the single point of failure for every failure report.**
  Nine cycles have now routed bad news to `thoughts.log` for window 1 to render.
  Nothing watches whether the thing rendering it is alive; `crt-console.sh` runs
  it as `./crt-monologue.py; exec bash`, so a crash leaves a bash prompt on the
  tube and every subsequent report goes to a file nobody is drawing. Not built —
  it is the supervisor question (ranked item 8), and I did not want to invent a
  watchdog unasked. Flagged as question 4 below.
- **`last_line()` exists in two files and `load_display_margins` is now reachable
  from three.** Unchanged from last cycle's question 4, one instance worse:
  `crt-monologue.py` now reaches `crt-pager.py`'s margin loader by `importlib`
  `exec_module` (the pattern `crt-secretary.py` established), because `bin/`
  scripts have hyphens in their names and cannot import each other. It works and
  it is guarded, but reaching into another *script* to borrow a function is not a
  module system.
