## 1. A scan that reached nothing — `0fc83a6`, `967af9c`

`crt-console.sh` made `book` the boot-default window for one specific reason,
written in its own comment and proven live on 2026-07-21: the scanner is a USB
HID keyboard, and it types into whatever window has focus. That is why
`crt-book-console.py` reads its own stdin at all.

The idle-lean layout selects the screensaver instead:

```
crt-console.sh:278   CRT_NO_IDLE_CLAUDE=1 -> tmux select-window -t claude:0
```

`.claude/SESSION-STATE.md` records that flag as persisted in potato's
`~/.bash_profile` and verified live after a reboot on 2026-07-23. So:

```
scan a book  → digits + Enter into crt-screensaver.py's pane
             → nothing reads that stdin
             → no scanner.log line, no question, no answer window,
               no training row
             → the tube keeps breathing
```

Every link of the funnel after the scan was fine. Nothing ever reached them.
And the failure is silent by construction — the screen shows a sleeping potato
before the scan and after it, so there is nothing to notice.

**Two halves, because it takes both.** `crt-screensaver.py` now reads its own
stdin and forwards anything ISBN-shaped to `~/.crt/scanner.log`, which
`crt-book-console.py` already tails — an existing wired path, not a new one.
Forwarding rather than handling: the idle face keeps no database and no book
logic, which is the whole reason that layout exists on a 1GB Pi.

That alone would still have drawn the question onto an unfocused window, so
`crt-book-console.py` now brings itself to the front when a scan lands, and
hands the tube back to the idle face when the question times out. That second
half is not politeness — without it the idle-lean layout loses its idle face
permanently on the first scan, and the fix becomes a second bug.

It is not a yank. A scan is a deliberate physical act by the person standing at
the console, and the question is what they just asked for — the same posture
`crt-secretary.py` already takes when an utterance escalates to Claude. What it
will not do is take the tube off a window someone chose by hand: if you pressed
prefix+1 to read window 1 while a question was up, you keep it.

**A failed lookup takes the tube too.** "Couldn't find that book" is just as
invisible on an unfocused window, and leaves someone waiting on a screen that
never changed. And if the switch itself fails, that goes to window 1 once per
cause — this is the line that says your scan *did* register and you simply
cannot see it.

**Tests: 12 in `tests/test_scan_reaches_the_tube.py`, 10 fail against the
parent; 10 in `tests/test_screensaver_forwards_scans.py`.** The two
load-bearing ones run the real `crt-book-console.py` against a fake `tmux` on
PATH — the shim idea `test_console_book_game_layout.sh` already uses — and
watch the `select-window` actually happen, on a scan and back to the idle face
after. Not "a helper function exists."

## 2. One home for what a scan looks like — `3a687d4`

Pure refactor, no behaviour change, but it is what made the above safe. A scan
line is now a contract between three processes, not a detail inside one file: a
line the screensaver writes in a shape the console rejects is indistinguishable
from no scan at all — the exact failure this cycle is about, one layer down.

`bin/crt_scan_line.py` holds the ISBN shape and both directions of the
`scanner.log` line. `crt-book-game.py` and `crt-book-console.py` re-export from
it. The screensaver imports only it: loading `crt-book-game.py` to reuse two
functions would drag `sqlite3` and `urllib` into the window whose entire
purpose is holding no brain. There is a test asserting exactly that, asked of a
fresh interpreter rather than of the source text.

Same move as `crt_wake_gate.py` last cycle. It is also the fifth underscored
module in `bin/`, which is question 8 on the list below, still unanswered.

## 3. An env var that would have been silently inert — `041f592`

`CRT_IDLE_FACE_WINDOW` tells the book window where to hand the tube back.
Set-but-not-exported is how the entire CTL-file mute/unmute duck sat dead on
potato until `fe46ac1` found it on 2026-07-24 — and reading the script and
seeing the assignment is what missed it that time.

So the fake-tmux shim now records the environment each window would inherit,
and the layout test asserts both answers: `0` in the idle-lean layout, unset in
the historical one where `book` is itself the idle face. Verified by deleting
the export and watching it fail, not by trusting that it would.

`crt-console.sh` also unsets it in the other branch: re-running the script in a
shell that booted idle-lean earlier would otherwise release focus to a window 0
that now holds a live Claude.

## 4. Stress-test of what I touched

The failure modes this project actually has, checked against tonight's change
rather than against the code compiling:

- **Two writers on `scanner.log` now.** Line-sized `O_APPEND` writes, the
  posture already in use. The console's self-echo suppression is keyed to lines
  *it* wrote, so a forwarded line is correctly seen as a real scan.
- **Double-handling a single scan.** Cannot happen: keystrokes go to exactly
  one window. If focus changes mid-scan the two halves are each non-ISBN and
  both get dropped — inherent to a keyboard-wedge scanner, not new.
- **A focus fight with `crt-window-switcher.py`.** The release only fires on
  the scan→idle transition, so a switcher-initiated return to `book` does not
  trigger one back. Checked the reverse case too: if Claude took the tube
  mid-question, the release sees `mono` active and declines.
- **No tmux at all** (running the console by hand): `select_window` fails
  through `OSError`, reports once, and the window keeps working. The take
  happens inside `main()`'s `LoopGuard`, so even an unexpected raise reaches
  window 1 rather than ending the window.
- **The screensaver's forwarder is a daemon thread** — a blocked stdin read
  cannot stall the animation, EOF cannot keep the process alive, and a broken
  `scanner.log` returns rather than raising. `--once` does not start it.
