## 1. The wake gate read stt-fixups.json once, at boot — `0ccdf13`

`bin/stt-fixups.json` is where this console keeps what it has learned about how
this room's mic renders the wake word. Three things write it while the engine is
up:

- the `stttrain` window — `crt-stt-training-merge.py --loop`, every 10 minutes;
- `crt-calibration-game.py`'s wake round — **a live human confirming a mishear
  with their own ear**, which is the strongest evidence this project ever
  collects about anything;
- a person with an editor.

Its only consumer read it once:

```python
FIXUPS = load_fixups(FIXUPS_PATH)
def addressed_to_console(text, wake_word=WAKE_WORD, fixups=FIXUPS):
```

Two binds, not one. The module-level read happens at import; the default
argument then freezes that dict at def-time, so even reassigning `FIXUPS` later
would not have reached the gate. On a console that stays up for days, every
alias confirmed after boot did nothing until the next restart — and every
surface said otherwise. The game printed `Saved`. The merge loop printed
`auto-merged`. The word still did not wake it.

The gate now reads through a `FixupsFile` that re-reads when the file's
`(inode, mtime_ns, size)` changes — **one `os.stat` per utterance**, not per
audio chunk. Three fields because `os.replace()` lands a new inode and a hand
edit can fall inside a single filesystem timestamp tick.

A failed re-read **keeps the last good set** rather than dropping to `{}`. An
alias that silently stops working is, from where the person is standing,
identical to being misheard again. The failure is reported once per distinct bad
state, on the same three surfaces as a dispatch failure, and it names which set
is actually in force — `keeping the 4 I already had` and `exact 'claude' only
until it parses` are different nights.

Reloads announce **only** the added entries whose intent IS the wake word. A
Book-Game-derived `friction` → `fiction` changes nothing about this gate (the
merge script's own header is honest about that); naming it would imply
otherwise.

**Companion fix, `crt-calibration-game.py`:** it saved with `open(path, "w")`,
which truncates the real file before writing a byte. A crash or a full SD card
mid-dump took every hand-confirmed entry in a git-tracked file holding judgments
that cannot be re-derived. Now temp file + `os.replace`, the way
`crt-stt-training-merge.py` already did it — which also means the newly-live
reader can never land inside a half-written file.

**18 tests** (`tests/test_fixups_reload.py`), **17 failing against the parent**;
the 18th is the guard that an explicit `fixups=` dict still wins. They load the
real `crt-stt-solo.py` with `CRT_STT_FIXUPS` pointed at a temp file and then
change that file, because the defect was in module-level wiring, not in a
function that could be handed a dict. One of them found a real bug in the fix
before it shipped: "no failure recorded yet" was initialised to `None`, which is
exactly what `fixups_signature()` returns for a **deleted** file — so a deleted
fixups file was the one failure the de-duplication would have swallowed.

## 2. Window 1 could not be read by hand — `016d816`

`crt-window-switcher.py`'s header promises it will *"never yank focus away from
something someone deliberately switched to by hand."* The check backing that
promise is:

```python
if active_window != claude_view_window:
    return False
```

which protects every window except the one it switches away from. Walk up an
hour after the last exchange, press prefix+1 to read the monologue:
`last_active` is ancient, so `now - last_active >= 30` is trivially true; `mono`
is displayed, so the guard does not fire. You are on `book` again within one
poll — two seconds — and again two seconds after your next attempt. The
auto-return had no notion of an exchange being *finished*, only of one being
*old*, and old is a condition that never stops being met.

That window is the one background window CLAUDE.md says is meant to be looked
at, and it is where every honest-failure line the last ten cycles added comes
out: capture death, a dead whisper server, an unspoken reply, a phone that never
rang, an utterance nothing handled, and as of tonight a fixups file that would
not parse. Last cycle (`6aecc39`) fixed that window drawing 24 rows into a
15-row pane. This is the other half of being able to see it.

An exchange is now **spent** once it has been returned from — the loop remembers
which `last_active` value it acted on, and only a fresh touch of the state file
(`crt-secretary.py`'s `touch_claude_active()`, which writes `time.time()`, so
always a new value) re-arms it.

**Second defect in the same three lines:** `subprocess.run(["tmux",
"select-window", ...])` with the status discarded and stderr thrown at a pane
nobody looks at. A `select-window` that cannot work — no such window, session
renamed, server gone — was indistinguishable from one that did, and the only
symptom was a tube that stayed put. It now returns `(ok, detail)` and reports
once per distinct cause on window 1 itself, the very screen a failed switch
strands you on. The part that needed care: it does **not** mark the exchange
spent on a failure, so one bad tmux call cannot end the auto-return for the rest
of the console's uptime.

**8 new tests, 7 failing against the parent.** Three run the real loop as a
child process against a fake tmux that logs its own invocations, because both
changes live in `main()`'s state rather than in a pure function: with the
displayed window pinned to `mono`, the loop must issue exactly **one**
`select-window` over ~20 polls, **two** after the state file is touched again,
and many-but-reported-once when `select-window` fails. The fake tmux is a Python
file, not a shell stub (`cdf05cc`'s lesson).

## 3. New issues found

- **`crt-stt-training-merge.py --loop` has no guard around its pass.**
  `while True: run_merge_pass()` — an `OSError` from the write (ENOSPC on a Pi
  SD card is the realistic one) ends the training loop for the rest of the
  console's uptime, silently, leaving a bash prompt in the `stttrain` window.
  Same shape as this cycle's other two findings, one level further out. Not
  fixed tonight: it is the third instance of "a background window dies and
  nothing notices", and that is the supervisor question (ranked item 8, and
  question 4 below) rather than three separate patches.
- **`crt-book-answer-listen.py` grades inside an unguarded `for` loop** over its
  stt.log tail. One raising grade — a malformed question row, a sqlite error —
  ends the last link of the Book Game funnel, which is a stability-bar item.
  Same call as above.
- **The env var for the fixups path is spelled two ways.** `CRT_STT_FIXUPS` in
  `crt-stt-solo.py` and `crt-calibration-game.py`; `CRT_STT_FIXUPS_PATH` in
  `crt-stt-training-merge.py`. They agree on the default, so nothing is broken
  today; setting either one alone splits the writer from the reader. This is
  ranked-backlog item 1's config sprawl, now with a fourth instance.
