## 1. One env line, two layouts — `0d97295`

`crt-console.sh` hands the stt window `CRT_TMUX_PANE=0.0` on a single line,
for both layouts. What sits on window 0 is not the same in both:

```
CRT_NO_IDLE_CLAUDE unset   window 0 = claude          a live Claude Code pane
CRT_NO_IDLE_CLAUDE=1       window 0 = crt-screensaver.py   the potato
```

The second is the layout potato boots. Two engines typed into it believing a
brain was behind it.

**The engine.** Single-word CONTROL utterances — `yes no okay go next back up
down clear cancel` and a dozen more — deliberately **bypass the wake gate**;
they are meta-interactions with whatever is on screen. So any ambient one of
them in the room was sent as a keystroke to `claude:0.0`, i.e. into
`crt-screensaver.py`'s stdin: echoed onto the potato by the tty, `Enter`
scrolling the frame, `Escape` painting `^[`, nothing anywhere able to act on
any of it — and the **"control" earcon beeping as though something had
happened**.

**The secretary.** The entire escalation path, whenever
`CRT_CLAUDE_REMOTE_PORT` is 0 — which is exactly what `crt-mandark.sh off`
writes, a command whose own help calls it "keep the brain local/onsite (or
none)". In this layout there is no local brain, and `tmux send-keys`
**succeeds** — the pane is real, it just holds a screensaver — so
`send_to_claude()`'s delivery check passed and `wait_for_claude_reply()` went
on to diff the potato's own frames looking for an answer. Since last cycle's
`4f7c17e` that caption **moves every 8s**, so the pane text genuinely changes:
the "reply" can come back as the caption and be spoken into the earpiece as
Claude's answer.

The rule is one string comparison and it now lives once, in `bin/crt_config.py`
(the file opened for exactly this — "one place to resolve a config value that
more than one script needs"): the pane is the idle face when its window matches
`CRT_IDLE_FACE_WINDOW`, which `crt-console.sh` exports **only** in the
idle-lean layout, before any window is created. With the var unset — the
historical layout — every caller behaves byte-for-byte as it did.

Both callers refuse and say so rather than going quiet:

- the secretary through the honest line it already had for an utterance that
  never left the building (`BRAIN_UNREACHABLE_LINE`, plus `oops`), and
  `capture_pane()` returns `None` there as a second brace;
- the engine through window 1 once (the cause never changes, and this can fire
  on any stray word) and its own pane every time.

18 cases, including that the historical layout still sends both halves of a
free-text send and that the remote route never reaches this branch at all.

## 2. The answer nobody could see — `c2473b4`

`handle()` switches the tube to `mono` the moment a request escalates, because
that window is where a Claude exchange is meant to be visible. What fills it is
`thoughts.log`: `log_user_thought()` writes the person's own words there, and
`crt-claude-bridge.py` writes Claude's — by tailing Claude Code's **local**
session transcript under `~/.claude/projects/`.

Since 2026-07-23 the brain runs on mandark. That transcript is on mandark;
potato's `bridge` window tails a directory the remote Claude never writes to.
So on the **success** path nothing wrote the answer down anywhere: `[you] ...`
on window 1, the tube switched to it on purpose, the earpiece speaking, and the
screen unchanged from before the question. That is the same blank window
`_report_bad_news()` was written to prevent on the *failure* path — the
migration took the brain and left this half behind, the way it left the scan
path behind (`0fc83a6`) and the CTL file behind (`fe46ac1`).

`route_claude_reply()` now mirrors **what it speaks** to window 1, and only
when the brain is remote — with a local brain the bridge is already doing this
job and a second copy would double every reply on a fifteen-row screen. The
long case mirrors its spoken summary, not the whole answer; the full text still
goes to the printer, and flooding window 1 is precisely what the bridge's
marker filter exists to prevent.

## 3. Stress-test of what I touched

Against this project's actual failure modes, not against it parsing:

- **The capture loop got faster, not slower.** The engine's new branch replaces
  two `subprocess.run` calls with a `print` and (once) a best-effort append, so
  there is no new way for `emit()` to stall the sole mic reader.
- **A stray word cannot flood window 1.** One line per process, then the stt
  pane only. Same once-per-distinct-cause rule `crt-window-switcher.py` uses.
- **The Book Game is untouched by the suppression.** The utterance reaches
  `stt.log` before any of this runs, so a spoken "yes" still reaches
  `crt-book-answer-listen.py` exactly as before — asserted by that file's own
  cases, still green.
- **The earcon change cannot silence the other one.** `EARCON_ON_ADDRESSED`
  sits on the `elif`, which only ever fires for non-control text; checked by
  reading the branch, not by assuming.
- **A broken `crt-think.sh` costs nothing.** The mirror swallows `OSError` and
  the spoken answer still happens — a case in the new file.
- **The report string is snapshotted beside the decision**, not rebuilt when it
  is printed; a message that re-reads the environment later can describe a
  configuration that was not the one acted on. (Caught by the first version of
  the test printing `CRT_IDLE_FACE_WINDOW=` empty.)
- **What I did not do:** route control keys to the remote brain. That needs a
  `KEY` verb in `crt-remote-claude-bridge.py` and a deploy onto mandark —
  question 1 below, your call, not an unattended one.
